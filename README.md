# Регмонитор — агент мониторинга регулирования частных инвестиций

Автономно отслеживает проекты документов, регулирующих финансовые операции
в сфере частных инвестиций в России: **ЦБ, Минфин, Госдума, Совет Федерации**,
включая стратегические документы типа **ОНРФР**. Ежедневно присылает отчёт
на почту и отдельно — срочные уведомления.

Работает на голой стандартной библиотеке Python 3.9+: никаких зависимостей,
нечему ломаться при обновлении системы.

---

## Быстрый старт

```bash
cd ~/Регмонитор
python3 -m regwatch doctor        # проверить источники, прокси и почту
```

`python3 -m regwatch` требует, чтобы вы находились в папке проекта.
Чтобы запускать откуда угодно — есть `regwatch-cli`, он сам находит проект
и подхватывает `~/.regwatch.env`:

```bash
~/Регмонитор/regwatch-cli doctor
```

Удобнее один раз завести псевдоним:

```bash
echo 'alias rw="~/Регмонитор/regwatch-cli"' >> ~/.zshrc
```

После `source ~/.zshrc` работает просто `rw doctor`, `rw run`, `rw stats`.

Затем настроить почту:

```bash
cp .env.example ~/.regwatch.env && chmod 600 ~/.regwatch.env
# вписать REGWATCH_SMTP_PASSWORD (для Gmail — App Password, не основной пароль)
```

Заполнить базу, чтобы первый отчёт не содержал весь архив:

```bash
python3 -m regwatch baseline
```

Поставить на расписание:

```bash
./install_schedule.sh
```

## Архитектура

Пять слоёв. Каждый падает независимо: сбой одного источника не роняет прогон,
сбой почты не теряет отчёт — он остаётся в `reports/`.

```
┌─ 1. СБОР ──────────────────────────────────────────────────┐
│  regwatch/sources/*.py — 14 коллекторов                     │
│  ЦБ (RSS+HTML) · pravo.gov.ru (JSON API) · Минфин · СФ      │
│  СМИ (RSS) · СОЗД и regulation.gov.ru (через прокси)        │
│  http.py: ретраи, троттлинг по хосту, пер-хостовый прокси   │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─ 2. СОСТОЯНИЕ ─────────────────────────────────────────────┐
│  store.py — SQLite                                          │
│  items · events · scores · runs · source_health · deliveries│
│  Дедупликация по хешу; отдельно ловится смена стадии        │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─ 3. ОЦЕНКА ────────────────────────────────────────────────┐
│  relevance.py + topics.json                                 │
│  19 тем × вес · вес органа · вес типа документа             │
│  затухание по возрасту · штраф за шумовые маркеры           │
│  → релевантность 0..1 и срочность critical/high/normal/low  │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─ 4. ОТЧЁТ ─────────────────────────────────────────────────┐
│  report.py — Markdown в архив + HTML для письма             │
│  группировка по срочности · сроки подачи замечаний          │
│  контакты для комментариев · здоровье источников            │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─ 5. ДОСТАВКА И РАСПИСАНИЕ ─────────────────────────────────┐
│  deliver/mailer.py — SMTP, пароль только из окружения       │
│  launchd: ежедневно 09:30 + проверка срочного каждые 3 ч    │
└─────────────────────────────────────────────────────────────┘
```

### Почему так

- **Детерминированный сбор, а не «спросить модель».** Парсеры дают
  воспроизводимый результат и не выдумывают несуществующие законопроекты.
- **Состояние в SQLite.** Агент отличает новый документ от обновлённого и
  ловит смену стадии — это и есть суть мониторинга, а не просто лента новостей.
- **Тематика вынесена в `topics.json`.** Правится без кода; после правки —
  `python3 -m regwatch rescore`.
- **Срочное отделено от текущего.** Ежедневный отчёт не будит ночью,
  а `--alert` шлёт письмо только при `critical` и молчит, когда нечего сказать.

### Госдума: почему СОЗД, а не API

У Думы есть официальное API (`api.duma.gov.ru`), и оно доступно по HTTP
напрямую, без прокси. Казалось бы, идеальный источник. Но объявлением
от 01.01.2026 Дума **временно отключила** методы «Поиск по законопроектам»,
«Программа законодательной деятельности» и «Результаты законодательной
деятельности», прямо отослав к СОЗД.

Коварство в том, что поиск продолжает отвечать `200` и отдавать данные,
замершие на 14.02.2025. Агент, который на это положится, будет молча
уверять, что в Думе ничего не происходит.

Поэтому источник `duma_api` написан, работоспособен, но **выключен**, а его
коллектор проверяет свежесть: если самое позднее событие старше 120 дней,
он отказывается отдавать данные и пишет об этом в отчёт. Когда Дума
закончит работы, источник оживёт сам — править код не придётся.

Законопроекты берутся из СОЗД (`sozd`) парсером. Он требует прокси, но
отдаёт актуальные стадии. Срочность определяется по коду стадии, а не по
словам: `1.x` — внесение, `3.x` — чтения, `8.x` — опубликование.

### Доступ к regulation.gov.ru

Оба портала **отбрасывают TLS-рукопожатие с не-российских адресов**.
Проверено: TCP-соединение устанавливается, ClientHello уходит, ответа нет.
Это не сбой агента и не лечится заголовками или таймаутами — нужен российский IP.
Остальные госсайты (ЦБ, Минфин, СФ, pravo.gov.ru) так не фильтруют и работают напрямую.

Агент маршрутизирует **только эти два домена** через прокси, остальные идут
напрямую. Достаточно одной строки в `~/.regwatch.env`:

```bash
REGWATCH_PROXY=socks5h://127.0.0.1:1080
```

и включить источники в `config.json`:

```json
"sources": { "sozd": {"enabled": true}, "regulation": {"enabled": true} }
```

Варианты, как получить российский IP, — в разделе ниже.

## Туннель через свой компьютер в России

Самый дешёвый путь: `ssh -D` превращает вашу машину в России в SOCKS5-прокси.
Отдельный сервер не нужен, платить не за что.

> SOCKS5 стандартная библиотека Python не поддерживает, поэтому он реализован
> в `regwatch/socks.py` (RFC 1928). Проверяется в `selftest.py`.

### Шаг 1. Включить SSH на машине в России

- **macOS** — Системные настройки → Основные → Общий доступ → Удалённый вход
- **Windows 10/11** — Параметры → Приложения → Дополнительные компоненты →
  «Сервер OpenSSH», затем в PowerShell от админа:
  `Start-Service sshd; Set-Service -Name sshd -StartupType Automatic`
- **Linux** — `sudo apt install openssh-server && sudo systemctl enable --now ssh`

### Шаг 2. Сделать её доступной снаружи

Домашний интернет почти всегда за NAT с «серым» адресом — напрямую подключиться
не выйдет. Выбирайте по ситуации:

| Ситуация | Что делать |
|---|---|
| Серый IP (обычный домашний интернет) | **Tailscale** — поставить на оба компьютера, войти одним аккаунтом. Пробивает NAT сам, настраивать роутер не надо. `tailscale ip -4` на российской машине покажет адрес вида `100.x.x.x` — его и укажете |
| Белый статический IP | Пробросить порт 22 на роутере, указать внешний IP |
| Есть свой VPS | Обратный туннель с российской машины: `ssh -R 2222:localhost:22 user@vps` |

Tailscale сам по себе российского адреса не даёт — он лишь соединяет ваши
устройства. Российский IP берётся оттого, что наружу, к СОЗД, запрос уходит
**с той машины**, через `ssh -D`.

### Шаг 3. Вход по ключу, без пароля

Обязательно: туннель поднимается в фоне с `BatchMode=yes` и на запрос пароля
просто зависнет.

```bash
ssh-keygen -t ed25519 -C "regwatch"
ssh-copy-id -i ~/.ssh/id_ed25519.pub ПОЛЬЗОВАТЕЛЬ@АДРЕС
ssh ПОЛЬЗОВАТЕЛЬ@АДРЕС "echo связь есть"
```

Последняя команда должна ответить без запроса пароля.

### Шаг 4. Прописать в `~/.regwatch.env`

```bash
RU_SSH_HOST=100.x.x.x        # адрес из Tailscale или внешний IP
RU_SSH_USER=ваш_пользователь
RU_SSH_PORT=22
TUNNEL_PORT=1080
REGWATCH_PROXY=socks5h://127.0.0.1:1080
```

### Шаг 5. Поднять и проверить

```bash
./tunnel.sh run &      # разово; на постоянку его ставит install_schedule.sh
./tunnel.sh check      # дошли ли до СОЗД
python3 -m regwatch doctor
```

`./tunnel.sh check` должен показать `СОЗД: HTTP 200`.

### Шаг 6. Включить источники ГД

```json
"sources": { "sozd": {"enabled": true}, "regulation": {"enabled": true} }
```

После этого `install_schedule.sh` поставит туннель в launchd с `KeepAlive`:
он поднимется сам после обрыва связи, перезагрузки или пробуждения ноутбука.

**Важно:** российский компьютер должен быть включён и не уходить в сон,
иначе туннель рвётся. В настройках энергосбережения отключите засыпание —
или примите, что в это время источники ГД будут пропускаться (остальные
десять работают напрямую и от туннеля не зависят).

## Настройка тематики

`topics.json` — 19 тем: квалифицированный инвестор, ИИС, брокеры, ДУ, ПИФ,
ПДС/НПФ, ДСЖ/ИСЖ, ЦФА и криптовалюты, инвестсоветники, ценные бумаги, биржа,
защита прав инвесторов, инсайд, заблокированные активы, инвестплатформы,
маркетплейс, стратегические документы, иностранные бумаги, розничный инвестор.

Паттерны пишутся **основами слов**, без окончаний: `квалифицированн инвестор`
поймает все падежи. Раздел `noise` гасит шум — монеты, ОСАГО, ипотеку, курсы валют.

## Пороги

`config.json → thresholds`:

- `report_min_relevance` (0.45) — попадание в ежедневный отчёт
- `alert_min_relevance` (0.70) + `alert_urgencies` (`critical`) — срочное письмо
- `max_items_per_report` (60) — потолок объёма

## Доставка отчётов

Каналы складываются: что настроено, туда и уходит.

| Канал | Что нужно | Что приходит |
|---|---|---|
| **Telegram** | токен бота и id канала в `~/.regwatch.env` | дайджест со ссылками; к дневному отчёту приложен полный файл |
| **Уведомление macOS** | ничего | сводка на экране; работает всегда как страховка |
| **Почта** | `email.enabled: true` и пароль приложения | письмо с полным отчётом |
| **Файлы** | ничего | `reports/` — Markdown и HTML, всегда |

Привязать канал Telegram:

```bash
python3 -m regwatch telegram-setup   # найдёт канал, куда добавлен бот
python3 -m regwatch telegram-test    # пробное сообщение
```

Бот не пишет первым: в канал его добавляют администратором с правом
публикации, в личный чат пользователь заходит сам. Канал удобнее — у него
есть архив с поиском, и подписчикам ничего настраивать не нужно.

Секреты читаются из `~/.regwatch.env` при любом запуске — и через обёртки,
и напрямую через `python3 -m regwatch`.

## Ретранслятор в Yandex Cloud (вместо публичного прокси)

Публичный прокси живёт дни: когда он умирает, Госдума и Совет Федерации
выпадают из мониторинга. Функция в Yandex Cloud решает это надолго —
она работает на российских серверах, и для госсайта запрос выглядит местным.
Бесплатного лимита (1 000 000 вызовов в месяц) хватает с огромным запасом:
агент делает порядка сотни в сутки.

Код функции — в папке `yandex_function/`.

### Что делать

1. Зарегистрируйтесь в Yandex Cloud, создайте каталог и платёжный аккаунт.
   Карта нужна для подтверждения, бесплатный тариф с неё не списывает.
2. **Cloud Functions** → создать функцию → среда выполнения **Python 3.12**.
3. Редактор: способ **ZIP-архив** или ввод кода вручную. Содержимое
   `yandex_function/index.py` — в файл `index.py`, `requests==2.32.3` —
   в `requirements.txt`.
4. Точка входа: `index.handler`. Таймаут: **30 секунд**. Память: 128 МБ.
5. Переменные окружения: **TOKEN** = длинная случайная строка латиницей.
   Сгенерировать: `python3 -c "import secrets,string; print(''.join(secrets.choice(string.ascii_letters+string.digits) for _ in range(40)))"`
6. Поставьте галочку **Публичная функция** и сохраните.
7. Скопируйте адрес функции с вкладки «Обзор».

Впишите в `~/.regwatch.env`:

```
REGWATCH_RELAY_URL=https://functions.yandexcloud.net/d4e...
REGWATCH_RELAY_TOKEN=тот же TOKEN
```

Проверьте:

```bash
python3 -m regwatch relay-test
```

Когда все три сайта ответят — очистите `REGWATCH_PROXY`: прокси больше не нужен.

### Почему именно так

**Токен в заголовке, а не в адресе.** В строке запроса он осел бы в журналах
Яндекса и в истории обращений. Заголовок `X-Relay-Token` туда не попадает.

**Ответ в base64.** Госсайты часто отдают windows-1251. Если возвращать
текстом, кодировка угадывается по дороге и кириллица превращается в мусор.
Байты доезжают как есть, разбирает их агент.

**Белый список сверяет имя узла, а не подстроку.** Проверка
`"duma.gov.ru" in url` пропустила бы `duma.gov.ru.злодей.рф`. Функция
сравнивает именно хост, поэтому открытым прокси для посторонних не станет.

**Маршрутизация не меняется.** Через ретранслятор идут ровно те же сайты,
что перечислены в `proxy.hosts` — госпорталы. Почта, Telegram, Apple и GitHub
как шли напрямую, так и идут. Ретранслятор старше прокси по приоритету:
когда он задан, прокси не используется.

## Уведомления на телефон (web push)

Канал не зависит от Telegram: уведомления доставляет сам браузер, блокировать
тут нечего. Цена — приложение нужно один раз разместить в интернете, потому что
телефон не может открыть страницу, лежащую на вашем Mac.

### Что уже сделано

Ключи VAPID сгенерированы (приватный в `~/.regwatch.env`, публичный в
`webapp/config.js`), приложение собрано в папке `webapp/`, отправка подключена
к агенту. Шифрование web push не входит в стандартную библиотеку Python,
поэтому оно вынесено в отдельное окружение `.venv-push/` — **ядро агента
осталось без зависимостей** и не сломается от обновления системы. Если
окружение удалить, push просто отключится, остальные каналы продолжат работать.

### Шаг 1. Опубликовать папку webapp

Бесплатно через GitHub Pages, без установки git — файлы загружаются мышкой.

1. Заведите аккаунт на github.com, если его нет
2. **New repository** → имя, например `regwatch`, тип **Public**, создать
3. **uploading an existing file** → перетащите всё содержимое папки `webapp/`
   (именно содержимое, не саму папку) → **Commit changes**

   Вложенных папок внутри `webapp/` нет намеренно: форма загрузки GitHub
   разворачивает папки в корень, и ссылки на отчёты обрывались бы. Всё лежит
   плоско и переносится как есть.
4. **Settings** → **Pages** → Source: **Deploy from a branch**, ветка `main`,
   папка `/ (root)` → **Save**
5. Через пару минут наверху появится адрес вида
   `https://ВАШ-ЛОГИН.github.io/regwatch/`

> **Сделано 24.09.2026:** приложение опубликовано по адресу
> <https://landswerk1000-afk.github.io/regwatch/> и прописано в `config.json`.
> Страница закрыта от поисковиков (`noindex` + `robots.txt`): открыть её
> можно только по прямой ссылке.

Впишите этот адрес в `config.json`, чтобы уведомления вели на отчёты:

```json
"webapp_url": "https://ВАШ-ЛОГИН.github.io/regwatch/"
```

> **О приватности.** Бесплатный GitHub Pages публичен: страницу увидит любой,
> у кого есть ссылка. Сами документы — общедоступные акты госорганов, но если
> не хотите выкладывать даже подборку, удалите из загрузки папку `reports/`

### Шаг 2. Установить на телефон

**Обязательно на iPhone:** push работает только из приложения, добавленного
на экран «Домой». Из Safari уведомления не приходят — ограничение Apple,
обойти его нельзя.

1. Откройте адрес в Safari
2. **Поделиться** → **На экран «Домой»** → **Добавить**
3. Запустите **Регмонитор** с экрана «Домой» (не из Safari)
4. **Включить уведомления** → разрешить
5. Появится код устройства — нажмите **Скопировать код**

### Шаг 3. Зарегистрировать устройство

Код передаётся один раз на устройство:

```bash
python3 -m regwatch push-add '<вставьте код>'
```

```bash
python3 -m regwatch push-test    # пробное уведомление
python3 -m regwatch push-list    # устройства и состояние доставки
```

Устройств может быть сколько угодно: свой телефон, компьютер, телефон
руководителя. Каждое регистрируется своим кодом.

### Что происходит при сбое

Молчания не будет. Подписка, на которую push-сервис ответил 404 или 410,
удаляется автоматически — устройство отписалось. Если push не достал никого,
а событие срочное, отчёт уходит резервным каналом на почту; когда почта
не настроена, агент пишет об этом прямо в результат прогона. Уведомление
на экране Mac показывается всегда, а отчёты в `reports/` появляются
независимо от того, сработал ли хоть один канал.

Telegram намеренно оставлен включённым. Отключать его следует только после
того, как push отработает полный суточный цикл — обычный отчёт и хотя бы
один срочный алерт. Снять его можно будет так: убрать `TELEGRAM_*` из
`~/.regwatch.env`; код канала останется на месте и просто перестанет
использоваться.
